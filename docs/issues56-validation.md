# Issue 56: row-extension audit fixes

All ten findings from the original audit are fixed and verified on the rebuilt Windows package. The full requirement accounting below covers EXT-1–107: the original 97 IDs plus ten appended interaction/verification rules. Process, historical and future obligations are distinguished from runtime passes.

## Changes

- **F1**: Visible separators in both themes; independent reference corrected.
- **F2**: Final-layout resize and zoom anchoring stays aligned to the trigger.
- **F3**: Popup fits the actual zoomed viewport; labels wrap and keyboard navigation scrolls the focused choice.
- **F4**: Recovery dismisses menus; working focus returns for pointer and keyboard entry.
- **F5**: Full long targets wrap inside menus and context bars.
- **F6**: Outside pointer dismissal preserves the clicked input and subsequent typing.
- **F7**: Successful synonym withdrawal retains stable row focus.
- **F8**: Sibling context follows changed draft kinds and matches saved RDF.
- **F9**: Cleared class parents name the actual owl:Thing fallback.
- **F10**: 24-pixel chevron targets pass expanded Axe checks; the old test exclusion is removed.

The shared editor, relation matrix, 148/44-pixel action columns and approved Sibling behavior are preserved. The spec's reversed Narrow/Shallow table, omitted Sibling examples, folded-caption exception, old container-query wording and historical implementation claims are reconciled. Revision 1 remains byte-for-byte unchanged. Revision 2 and its normative README are tracked under tests/fixtures/extend-visual because specs/ is ignored. New expected images were generated exclusively from that independent HTML.

## Verification

- TypeScript: npm run typecheck passed.
- Domain: 342 tests passed across extension, synonym, Find state and creation suites.
- Rebuilt package: 77 distinct desktop cases have passing final results, with no skips or automatic retries: extend-audit, extend-visual, find-adaptive, find-stability and scoped find creation/extension/synonym cases.
- Visual: 30 isolated control comparisons plus two at-rest checks, light and dark, with zero differing pixels against fresh independent renders and stored baselines.
- Runtime audit: 107 records and 73 unaltered screenshots; docked and native detached windows, all four presentations, threshold/minimum sizes, both themes, 50–300% pane zoom, long names, recovery, keyboard and emulated coarse-pointer media. All recorded menus fit the viewport; all recorded last-item focus states are visible.
- Accessibility: expanded open-cluster Axe checks in both themes report zero violations; minimum target assertions include the chevron.

The first development regression run exposed recovery focus loss; it was corrected before this final package was built. Expanded checks also found that an already-focused menu choice could leave view during live resize/zoom. Position updates now reveal that choice without another keypress. The native-window helper was corrected to unmaximize before resizing after recovery. These earlier reports are retained with -initial suffixes; the final rebuilt package was checked afresh. That run passed 54 of 55 cases; an existing adaptive test measured its pane insets during native unmaximize and requested the wrong window size. Its helper now measures before restore starts. The complete 20-case adaptive suite was rerun on the same final package; all final case results pass without automatic retries. Counts deduplicate cases across these explicitly retained reports.

This is scoped evidence, not proof over every ontology or device. Physical touchscreen, external screen reader, forced-colors and mixed-monitor DPI sessions were not run. The historical find.html prototype is absent.
